## 一、产品概述

### 1.1 产品定位

**一句话**：把全球公民科学的观察数据做成一张"自然探索观察地图"——从引入 iNaturalist 与 GBIF 的海量自然观察资源起步，打开地图即可探索任何地方最近被记录到的自然事物，照片直出、时空可查、逐月苏醒。

自然地图志不是又一个记录工具（用户不在此产生数据），而是一座**呈现与解读引擎**：现阶段把 iNaturalist 与 GBIF 两大观察网络里散落的海量自然记录，翻译成普通人看得懂、愿意探索的地图体验；平台定位是**面向自然探索观察的通用地图**，生物多样性只是第一块拼图——未来将逐步引入非生物类自然观察资源（地形地貌、地质现象、天文气象等），成为探索整个自然的地图志。

### 1.2 背景与机会

- iNaturalist 已积累全球数千万条带照片的自然观察，中国主要城市（北上广深杭、成都、昆明、香港等）有活跃的观察者社区，但数据呈现形态原始：官网 Explore 页面向研究者，筛选门槛高、无中文体验、无物候视角；
- 中文互联网缺少"一座城市的生物现在怎么样了"的答案入口：观鸟记录中心等垂直产品只覆盖单一类群；
- 自然教育在中小学课后服务中快速增长，教师需要本地化、可视化、可直接投屏的素材；
- 公园城市与城市生物多样性评估需要公众可感知的数据出口；
- GBIF 汇聚全球数百家机构的观察网络（含博物馆标本与区域观测计划），与 iNaturalist 互补，为"从生物起步、走向整个自然"提供可扩展的数据基座。

### 1.3 差异化

| 对比对象 | 它们的形态 | 自然地图志的差异 |
|---|---|---|
| iNaturalist Explore | 面向贡献者的检索工具，英文，信息密度高 | 面向**探索者**的地图，中文优先，照片直出 |
| 国内观鸟记录中心 | 单类群（鸟） | 全类群：鸟、虫、哺乳、植物、真菌…… |
| 形色/识花君 | 拍照识别的工具属性 | 地图尺度的**时空呈现**：哪里有什么、何时出现 |
| 各城市绿化部门公报 | 年度静态报告 | 天级更新、可交互、可下钻 |

### 1.4 产品目标与成功指标

**产品使命**：让普通人在地图上重新看见并探索身边的自然。

| 指标类型 | 指标 | 目标（上线 3 个月） |
|---|---|---|
| 北极星指标 | 周活跃探索用户（打开地图并浏览 ≥1 个物种卡） | 1,000 |
| 规模 | 覆盖城市数 | 3 |
| 参与度 | 人均浏览物种卡数 / 次 | ≥8 |
| 参与度 | 物候页 / 物种详情页停留时长 | ≥90 秒 |
| 数据质量 | 数据新鲜度（观察发布到可查询，P95） | ≤2 小时 |
| 数据质量 | 物种鉴定状态准确率（research 级占比） | ≥60% |
| 合规 | 被数据源限流/封锁次数 | 0 |

### 1.5 非目标（明确不做）

- 不做用户观察记录上传（不做 iNat 的替代品，避免与数据源争抢贡献者）；
- 不做 AI 拍照识别工具（已有成熟产品）；
- 一期不做社交关系链（关注/评论/私信）。

│   ├── 物种逐旬出现曲线（P0）

### 3.2 关键功能验收要点

| 功能 | 验收要点 |
|---|---|
| 照片卡片 | 聚合簇缩放散开为缩略图卡片；卡片含照片、物种名（中/英/学名）、观察者、拍摄时间、版权署名；点击出大图 |

| 内容安全 | 用户可举报；运营隐藏后前端 5 分钟内不可见 |

## 四、数据策略

### 4.1 数据源档案（双源并行：iNaturalist v2 + GBIF）

| 项 | 内容 |
|---|---|
| 基址 | `api.inaturalist.org/v2`（OpenAPI 3.0 规范，完整 schema 见 `/v2/api-docs`） |
| 核心端点 | `/observations`（搜索）、`/taxa`（分类）、`/places`（地名）、`/observations/histogram`（时间直方图，只取计数不拉明细）、`/observations/species_counts`、`/observations/observers` |
| 响应投影 | v2 默认最小响应（仅 UUID），须以 `fields` 参数指定字段（逗号分隔 / RISON 编码 / `fields=all`）——按需取字段，响应体积极小 |
| 关键筛选参数 | bbox、d1/d2 日期窗、taxon_id、iconic_taxa 类群、quality_grade（research / needs_id / casual）、per_page 上限 200 |
| 官方地图瓦片 | **仅 v1 提供**：`api.inaturalist.org/v1/heatmap|points|grid/{z}/{x}/{y}.png` + UTFGrid JSON，接受与搜索一致的参数（taxon_id、iconic_taxa、quality_grade 等）——作为"全球视角"图层与本地数据叠加 |
| 物种分布瓦片 | **仅 v1 提供**：`api.inaturalist.org/v1/taxon_ranges/{id}/{z}/{x}/{y}.png`、`/v1/geomodel/{id}/...`——物种详情页的全球分布底图（使用源站 taxon id） |
| 特色端点 | `/taxa/{id}/wanted`（本区域未记录物种清单）、`/computervision/score_observation/{uuid}`（AI 鉴定建议） |
| 频率约束 | 硬限 100 次/分钟，官方要求 ≤60 次/分钟，且 <10,000 次/天 |
| 单查询上限 | 约 1 万条——历史回补必须按时间窗切片 |
| 照片策略 | 多尺寸 URL（square 75 / small 240 / medium 500 / large 1024 / original 2048）；**只存 URL 热链**，卡片用 medium、缩略用 square |
| 照片版权 | 域名区分授权：`inaturalist-open-data` 域为开放协议（可批量获取），`static.inaturalist.org` 域为非开放协议——展示必须保留 `©观察者 + 协议` 署名 |
| 坐标隐私 | 受威胁物种坐标被模糊化（公开为约 0.2° 网格中心）——前端标注"位置经保护性模糊" |
| 合规口径 | 数据源服务条款明确：API 面向应用开发、不支持数据抓取；批量历史数据应使用官方预生成导出（iNaturalist AWS Open Dataset） |

**GBIF Occurrence API（第二数据源，与 iNaturalist 双源并行采集）**

| 项 | 内容 |
|---|---|
| 基址 | `api.gbif.org/v1`（检索）；地图瓦片 `api.gbif.org/v2/map/occurrence/density/{z}/{x}/{y}@1x.png`（全球密度，全球视角可选图层） |
| 核心端点 | `/occurrence/search`（检索观察记录，支持 bbox、日期窗、taxonKey、媒体过滤）、`/species/match`（学名匹配回填 taxon）、`/species/{id}`（分类档案） |
| 价值 | 汇聚全球数百个数据发布机构的观察记录（含部分 iNat 之外的博物馆标本与区域观察网络），与 iNat 互补提升覆盖广度 |
| 去重口径 | 双源记录以 `source + 源站 ID` 为唯一键各自入库；GBIF 记录中 datasetKey 为 iNaturalist 数据集（50c9509d-22c7-4a22-a47d-8c48425ef4a7，institutionCode=iNaturalist）的转发条目跳过，dataset_key/dataset_title 落库供署名与对账 |
| 媒体策略 | 仅取带图片（`mediaType=StillImage`）且坐标公开的记录；照片 URL 热链，署名保留数据发布机构与协议 |
| 频率约束 | 无硬性限额，官方建议保持克制（本站默认 ≤60 次/分钟），长查询走异步下载作业而非同步 API |
| 图像版权 | 遵循各记录声明的许可协议（多为 CC0/CC-BY/CC-BY-NC）；展示保留 `©数据发布机构/观察者 + 协议` 署名 |

### 4.2 采集策略

**首次建库（双轨决策）**

| 方案 | 内容 | 取舍 |
|---|---|---|
| A（MVP 采用） | 采集近 24 个月 + research/needs_id，约数千次请求、1~2 天完成 | 合规快、成本低；物候深度历史用 histogram 统计端点补足（只拉计数） |
| B（v1.1 可选） | 首启用官方 AWS Open Dataset 全量导出，API 只做增量 | 明细历史完整；需处理导出文件格式与更大存储 |

**日常增量**

- 每小时一次增量同步（按更新时间水位），覆盖新增观察与事后鉴定变更（needs_id → research 的回流）；
- 双源并行：iNaturalist 与 GBIF 各自独立水位、独立节流（iNat ≤30 次/分钟、GBIF ≤60 次/分钟），按 `source + 源站 ID` 幂等去重入库；
- 日请求预算占用 <5%（各源独立预算），处于合规舒适区；
- 采集端内置节流与失败重试，单时间窗失败记录日志跳过、不阻塞整体；
- 删除对账：周度抽样比对 ID，静默下线；
- 分类（taxon）表每日低频刷新一次，观察记录冗余存类群字段避免联表。

### 4.3 数据口径

- 默认展示口径：research + needs_id（兼顾新鲜度与质量）；总览页可切换"仅 research"；
- "本月新星"、物种榜等统计口径在页面注明数据窗口；
- 物候曲线提供两种口径：本站明细口径（近两年）与全历史统计口径（直方图端点）。

## 五、系统架构概览

```
采集服务（控制台作业，可定时执行）
  ├─ 数据源 API 客户端 ×2（iNaturalist v2 + GBIF v1 端点封装，统一 UA 与独立节流）
  ├─ 超时/重试/熔断保护（任一源站不稳时跳过该源本周期，不拖垮作业与另一源）
  ├─ 增量水位管理（断点续采）
  ├─ 批量幂等入库（按源站 ID upsert）
  └─ 结构化运行日志
        ↓
数据库：PostgreSQL（近两年热数据；按年归档策略预留 SQLite 归档库）
        ↓
查询服务（Web API）
  ├─ 观察检索 / 物种榜 / 物候曲线 / 城市统计
  ├─ 组合筛选 + 分页 + 聚合，热门查询服务端缓存（约 10 分钟）
  └─ 时间展示按访客时区呈现
        ↓
前端（Vue 3 + MapLibre GL 单引擎 + supercluster 客户端聚合）
  ├─ 2D / 2.5D（倾斜 + 建筑挤出）/ 3D（地球仪 + 地形 + 天空）三种视图
  ├─ 照片卡片 / 类群着色 / 热力图 / 时间滑块
  └─ 叠加数据源官方瓦片（全球视角）与本地明细（城市视角）
```

## 六、数据模型概要

| 表 | 字段要点 | 说明 |
|---|---|---|
| `country` | ISO 3166-1 alpha-2 代码（唯一）、中/英文名、定位中心点经纬度 | 全球国家档案；种子内置全量 249 国（含定位坐标） |
| `province` | 国家归属、ISO 3166-2 区划码（同国唯一）、中/英文名、定位中心点经纬度 | 国家一级区划（省/州/都道府县/大区等泛称）；种子覆盖中国 34 + 主要国家 |
| `city` | 国家/省份归属、中/英文名、slug（全站唯一）、bbox 四至 | 全球城市档案；种子内置中国 67 城 + 全球首都 191 + 主要城市 104；**定位中心点不单独存储，由 bbox 中点推算**（接口返回 center） |
| `observation` | 源站 ID + 数据源（主键组合）、city_id、taxon_id、observed_on、lat/lng、photo_medium_url、photo_square_url、quality_grade、record_basis（人类观察/机器观察/标本）、dataset_key/dataset_title（GBIF 数据发布机构署名与去重锚点）、license（含 PDM）、identifications_count、user_login、positional_accuracy、create_time/update_time | 主档表；只存展示必需字段 |
| `taxon` | taxon_id + 数据源（主键组合）、学名、常用名（中/英）、iconic_taxa 类群（1~13 与 iNat 13 个 iconic 类群一一映射，含爬行动物；14=未知/无法归类）、祖先链、threatened 受威胁标记 | 供着色/筛选/物候聚合与保护标注 |
| `sync_cursor` | 数据源 × 城市 × 任务、水位时间戳、config 参数、上次运行统计 | 增量游标与采集运行档案（双源各建游标） |
| `emergence_stat`（预留） | city_id × taxon_id × 年份 × 旬（1~36）× 出现次数（全部 / 仅 research） | 预聚合物候表；数据量上来后启用，未启用时接口由明细实时聚合 |
| `emergence_history` | city_id × taxon_id × 月份 × 全历史出现次数 | 源站直方图缓存（全历史口径）；无缓存时接口以本站明细按月兜底 |
| `report` | observation_id、原因（0~4）、补充说明、联系方式、处理状态/处理人/备注 | 内容举报工单（公开站匿名提交，后台审核） |

## 七、API 设计

公开站接口由 `Rampage.NaturalistAtlas.WebApi` 提供（开发端口 5214），字段级契约见《自然地图志前端设计》§6。

| 端点 | 说明 |
|---|---|
| `GET /api/geo/cities` | 已启用城市列表：中/英文名、slug、国家/省份名、bbox 与由 bbox 推算的 center |
| `GET /api/geo/search` | 地点搜索：按国家/省份/城市名称（中/英）模糊检索（区划代码精确匹配），返回层级、上级名称、定位中心点；城市另返回 bbox 与 slug |
| `GET /api/observation/points` | 地图点位：组合筛选下的轻量点（id、坐标、类群、鉴定级别、展示名、方图），上限 8000（最大 10000）并返回 truncated 标记，供前端客户端聚合 |
| `GET /api/observation/list` | 观察卡片分页：类群 × 月份区间（可跨年）× 鉴定状态 × bbox × 日期窗 × 物种组合筛选 |
| `GET /api/observation/{id}` | 观察详情：卡片字段 + 大图、位置精度、鉴定次数、记录类型、城市名与源站原始链接 |
| `GET /api/species/rank` | 城市物种榜：按记录数 / 观察者数排序，支持组合筛选与物种名关键字，分页 |
| `GET /api/species/{id}?cityId=` | 物种详情：分类档案 + 本市记录数/观察者数/首末次日期 + 照片墙（最新 60 张）+ 本市分布点 |
| `GET /api/species/{id}/emergence` | 物候曲线：`mode=detail` 近两年逐旬（优先 emergence_stat，缺失时明细实时聚合）/ `mode=history` 全历史逐月（优先 emergence_history）；`researchOnly` 切换仅研究级；返回样本量 |
| `GET /api/phenology/matrix` | 物候矩阵：组合筛选下记录数 Top N（默认 30）物种 × 12 个月计数（忽略月份筛选） |
| `GET /api/stats/overview` | 城市总览：总记录、研究级数、物种数、观察者数、本月观察数、类群构成、本月新星、活跃观察者、最新源站发布时间 |
| `POST /api/report` | 内容举报：匿名提交（原因 0~4，选"其他"须填说明），请求头 `Idempotency-Key` 防重复提交，返回举报 id |
| 管理端 | 采集任务状态（双源）、数据源配置（iNaturalist + GBIF）、内容隐藏（需管理员权限；ManagementSite 站点） |

接口约定：

- 统一响应结构 `{ Code, Message, Data }`（Code=0 成功；Rampage 框架保留 C# 属性原名即 PascalCase，前端 http 层统一转为 camelCase）；
- 列表类接口分页，分页结构 `{ Pager: { PageIndex, PageSize, RecordCount, TotalPage }, DataList }`；
- 枚举一律以数字代码传输；观察日期 `observed_on` 为观察者本地日期字符串 `YYYY-MM-DD`，时刻类字段（observed_at、source_created_at）以 ISO 8601 UTC（带 `Z`）返回，前端按访客时区展示；
- 数组参数以逗号分隔（如 `iconic=1,6,9`），非法值静默忽略；鉴定级别缺省为 research + needs_id；
- 热门聚合查询服务端缓存 5~10 分钟（点位/榜单/详情 5 分钟，物候/总览 10 分钟）。

## 八、前端与交互要点

1. **照片卡片地图**（核心体验）：聚合簇随缩放散开为照片卡片——这是产品的第一印象，性能目标为首屏 ≤2 秒；
2. **类群着色**：固定调色板（鸟/哺乳/两栖/爬行/辐鳍鱼/昆虫/蛛形/软体/植物/真菌/其他动物/原生动物/色藻，另有"未知"兜底色），图例即筛选器；
3. **地点搜索定位**：地图搜索框输入国家/省份/城市名称（中英文均可），联想下拉后地图飞行定位——国家/省份用中心点、城市用 bbox 视野（并切换为当前城市）；
4. **多维视图**：同一 MapLibre 引擎切换 **2D**（平面墨卡托，锁定倾角）/ **2.5D**（55° 倾斜视角 + 建筑挤出）/ **3D**（地球仪投影 + 地形起伏 + 天空大气 + 山体阴影；低缩放为地球仪、放大后连续过渡到城市地形）三种模式，相机平滑过渡；
5. **双视角地图**：城市视角用本地明细（照片卡、热力），缩放至区域外（明显缩小到城市全貌以外，或视野离开城市）自动切换数据源官方瓦片（iNat 热力 / GBIF 密度），无缝衔接；
6. **底图**：默认使用免费开源的 OpenFreeMap 矢量底图（随主题切换 positron / dark / liberty 风格），可选 Esri 卫星影像；配置天地图密钥后提供天地图矢量/影像（国内合规底图，上线前须补审图号）；地形高程使用 AWS Terrain Tiles（Terrarium 编码）；
7. **三套可切换主题**：A「博物志·纸本」（浅色纸张质感、衬线标题）、B「夜观·萤火」（深色、萤光强调色，默认）、C「四季·光谱」（强调色随月份变化），主题同时作用于界面、底图配色与类群调色板；
8. **时间滑块"城市苏醒"**：按月/按旬播放——3 月山樱与早蝶 → 4 月候鸟过境 → 6 月萤火虫 → 10 月真菌季；
9. **物种详情页**：照片墙 + 本市分布点 + 官方分布范围底图 + 全年出现节奏曲线；
10. **物候矩阵**：物种 × 月份热力表，支持类群过滤与排序，一屏看尽城市的季节剧本。

前端路由：`/`（地图探索）、`/overview`（城市总览）、`/species`（物种榜）、`/species/:id`（物种详情）、`/phenology`（物候日历）、`/gaps`（集邮缺口，P2 占位）；地图常驻底层，页面以侧栏（桌面）/ 底部抽屉（移动）叠加；城市与筛选条件同步到 URL（`?city=&t=&m=&q=`）便于分享。

## 九、非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 地图首屏 ≤2s；查询接口 P95 ≤500ms；聚合统计走缓存 |
| 数据新鲜度 | 观察发布到可查询 P95 ≤2 小时 |
| 可用性 | 采集作业失败不影响查询服务；源站故障时本地服务完全可用 |
| 合规 | 严守双数据源各自频率约束（iNat ≤30、GBIF ≤60 次/分钟，日预算各 <5%）；零封锁记录 |
| 版权 | 所有照片展示保留作者与协议署名 |
| 隐私 | 不存储源站用户个人信息（仅公开昵称）；受威胁物种模糊坐标照实标注 |
| 国际化 | 界面中文优先，预留英文；物种名中/英/学名并列 |

## 十、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 数据源限流/封锁（ToS 定位为应用开发而非抓取） | 高 | 采集范围收窄（近 24 个月）+ 低频增量；历史深度用统计端点而非拉明细；预留官方全量导出通道 |
| 国内访问源站偶发不稳 | 中 | 采集端熔断跳过、本地服务不受影响；双源并行（iNaturalist + GBIF），任一源不可用时另一源照常补充数据 |
| 照片版权 | 中 | 卡片/大图全程保留 `©作者 + 协议`；仅热链不搬运文件 |
| 不当内容（罕见但需兜底） | 中 | 举报入口 → 运营隐藏 → 定期复盘；后台支持按 ID/作者隐藏 |
| 受威胁物种位置泄露 | 低 | 源站已做坐标模糊，前端照实标注；不做任何去模糊处理 |
| 数据冷启动（某城市记录稀疏） | 中 | 上线城市选观察活跃城市；稀疏城市展示"招募观察者"引导页而非空地图 |
| 物候口径误读（把观察热度当物候） | 中 | 曲线页注明口径与样本量；提供 research 级过滤开关 |

| 术语 | 解释 |
|---|---|
